Keep guidance beside the creative tool

Aside is designed for beginners who have a clear creative goal but are unfamiliar with the tools. Using a music video as the example, the concept organizes work across Suno, Sora and Premiere Pro into a sequence: plan in a desktop app, then follow contextual instructions in an overlay.

This case study draws on the Final Paper, Project Screens and Style Guide. Automatic generation, tutorial import and cross-app guidance are proposed behaviors; the deliverables are a Figma prototype and design documentation.

The gap between learning and doing

Moving between a text or video tutorial and a creative tool asks users to leave the task, remember the instructions, then return to act. Aside starts from this gap and keeps the current instruction beside the current task.

Low distraction

Keep guidance beside the task and preserve space for the creative tool.

Continuous flow

Maintain task context from the goal to the workflow and active work.

Stable hierarchy

Use consistent typographic logic so users can locate the current instruction.

Four key design decisions

01

Separate planning from execution

The System Layer creates, browses and manages workflows; the Work Layer provides guidance during creation. Keep complex choices in the standalone window and focus the overlay on the current task.

02

Offer three starting points

Aside Generate starts from a creative goal, Import from URL proposes converting tutorials into steps, and Discover offers community workflows. These entry points converge on the same guided sequence.

03

Adjust guidance to the task

Expanded shows full instructions, Focus keeps the current action in a slim horizontal bar, and Minimal retains a compact status and progress indicator. Dark and light appearances adapt to different workspaces.

04

Build hierarchy through typography

DO, WHY and IF STUCK distinguish action, explanation and help. Size, weight, spacing and opacity organize the content with consistent logic across both layers.

From content definition to interface iteration

The process moves through content, structure, layout and typography: define the information, revise wireframes through feedback, then unify different sizes and appearances within one system.

01

Define the content first

Define the goal, tools, skill level and workflow phases, then the current step, action, explanation, troubleshooting and progress. The paper identifies content-first design as more efficient than choosing typography after the visuals.

02

Refine the two-layer structure

The paper describes ongoing sketch revisions based on feedback, including adding a System Layer for creating and managing workflows before moving into the Work Layer during active work.

03

Adjust layout and information density

Combine a full vertical panel with a compact horizontal layout, then introduce different sizes, a Minimal mode and light appearance so guidance retains its priorities at different footprints.

04

Establish a reusable type system

Assign distinct roles to Nico Moji, Markazi Text and Inter, then establish shared hierarchy through size, weight, spacing and opacity. Refine color, text opacity and light appearance around a WCAG AA contrast goal.

The core journey starts with a goal

  1. Choose an entry point
  2. Describe goal & select tools
  3. Preview the workflow
  4. Follow steps while creating

The example is a 60-second music video with a night-drive mood: concept and mood board, audio in Suno, visuals in Sora, editing in Premiere Pro, then export and sharing. Projects and Account provide project status, personal workflows and saved items.

Final designs · two layers, one workflow

Switch between the System Layer and Work Layer, and select any original design to enlarge it. The narrow Work Layer panels are desktop overlays.

A visual system shared across both layers

Nico Moji carries the brand, Markazi Text distinguishes step titles, and Inter serves UI and body content. Secondary text uses 60% opacity in the System Layer and 80% in the dark Work Layer. Both layers share typographic logic while adapting to comfortable planning and compact in-task guidance.

Reflection and next steps

The central reflection in the paper is that typography belongs to the guidance system itself. Define the content before its hierarchy; changes to size, spacing or opacity affect how users identify the current action.

Further exploration

The paper proposes exploring variable fonts that respond to interaction. Further validation could examine window switching, comprehension of the three modes, and readability of small text and opacity levels in real workspaces. These are proposed next steps with no reported results.
